# Among the Shadows: branding and incident danger audio

The game display name is now **Pokémon: Among the Shadows**. A shared display-name module supplies the lobby/player HUD/operator UI/scenario label. The SVG title lettering, browser title, install manifest and export filenames also use the new name. Stored scenario IDs, versions, player credentials and browser settings retain their existing keys, so a display-name change does not invalidate rounds or saved preferences.

The root audio mixer now announces new authoritative incident IDs with a non-positional facility alarm. Both player terminals hear it even when the event is in another room. Pokémon arrivals use three lower-pitch rising/falling pulses; emergencies use four higher-pitch pulses. These are short original Web Audio sirens, independent of the recorded battle attack sounds. They run through the existing master/effects controls and limiter. The existing red border/banner continues to provide the visual warning, including reduced-flash preferences.

The prior materialization/emergency sound came through the spatial renderer with a 750-unit distance cutoff and distance attenuation, making remote emergencies effectively silent. The global alarm is now owned by the root audio layer, so it also works while a terminal overlay is open or the 3D renderer is loading. The renderer no longer duplicates the old local materialization/emergency beep.

Each incident is announced once per client session. Repeated snapshots, task changes and reconnections of the existing transport do not replay an acknowledged alarm. Emergency announcements take priority over Pokémon audio. An alarm is cancelled when its incident is resolved/cancelled or when play pauses/ends, the document is hidden, or sound is muted. Unmuting does not replay an already-announced incident. Unannounced fresh incidents can retry when audio becomes available; old incidents are not replayed as new arrivals. Browser audio still requires player interaction.
