# Cloud reconnect recovery

This revision fixes recoverable transport failures becoming permanent after eight retries. Transient closures retry with bounded backoff; scheduled function rotation retries after 100 ms. Explicit credential, ownership and policy failures still require rejoining/sign-in. Old socket callbacks cannot update a replacement connection. A 30-second authoritative-snapshot watchdog recovers an open socket that has stopped supplying state, and disconnect code/reason events are retained in a bounded in-memory diagnostic history.

Cloud polling now drains the latest input when queued work actually executes, rather than replaying an input captured before a slow database action. Sequence barriers preserve ordering around tasks/battles. Consequential work is bounded, duplicate resync requests coalesce, and close cleanup cannot produce an unhandled rejection. Routine function rotation moves from 240 to 285 seconds, within the configured 300-second Vercel function budget; rotation is still expected and is not an Internet fault.

Verification: cloud service tests pass, including delayed-action stop coalescing and action-ordering regressions. Browser tests pass for repeated scheduled rotations with the same player/session and for 360 ms simulated round-trip latency. Recovery policy tests pass. A previous full regression run passed 151 tests with one optional native PostgreSQL test skipped, before the additional ordering test. Production health returned HTTP 200 in two read-only checks (approximately 0.35–0.45 seconds); these do not measure gameplay load or prove production root cause. No production database records were changed.
